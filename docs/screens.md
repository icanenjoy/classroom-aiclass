## a. 어느 화면에도 안 붙는 엔드포인트

**없음.** 이 저장소에 존재하는 API 라우트는 `GET /api/questions`(`src/app/api/questions/route.ts`) 단 하나뿐이고, 이마저 `/sqld` 화면이 `fetch('/api/questions')`로 실제 사용 중이다. 이 라우트는 DB나 외부 서비스를 부르지 않고 `src/data/questions.ts`의 정적 배열을 그대로 JSON으로 감싸 반환하는 역할만 한다.

## b. 화면에 필요한데 엔드포인트가 없는 것

- **홈 화면 — 시험 목록 조회 API 부재**: `exams` 배열이 `page.tsx`에 하드코딩되어 있어 시험을 추가/수정하려면 코드 배포가 필요하다. 다만 `CLAUDE.md`에 명시된 대로 "쓰기/관계형 쿼리가 필요해지기 전까지 DB를 다시 들이지 않는다"는 의도된 설계이므로, 버그라기보다는 확인이 필요한 트레이드오프로 봐야 한다.
- **SQLD 화면 — 학습 진행 상태 저장 API 부재**: 채점 결과·브랜치 진행 상황이 `localStorage`에만 남고 서버에 저장되지 않아, 기기를 바꾸거나 브라우저 데이터를 지우면 진행 상황이 사라진다. 이것도 정적 파일 전환 당시의 의도된 설계(`CLAUDE.md` 스택 변경 이력 참고)이며, 다기기 동기화가 필요해지기 전까지는 우선순위가 낮다.
- **카카오뱅크 송금 화면 — 예금주 조회 API 부재**: `isRecipientMatch` 같은 검증 함수로 클라이언트에서 참/거짓만 판정한다. 실습용 시뮬레이션이라 실제 은행 데이터 연동이 필요 없는 것이 맞고, 여기서는 오히려 "엔드포인트가 없는 게 정상"인 케이스다.

## 참고: a/b에는 안 맞지만 발견한 이슈

- `GET /api/questions` fetch 실패 시 에러 처리가 전혀 없다 (위 표의 SQLD 에러 상태 참고). 엔드포인트가 없는 게 아니라 **있는 엔드포인트의 실패 케이스를 화면이 처리하지 않는** 문제라 a/b 어느 쪽에도 속하지 않지만, 실제로 API가 죽으면 사용자가 "불러오는 중..." 화면에 멈춰버리므로 별도로 기록해둔다.
