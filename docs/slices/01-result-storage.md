# 기능 1: 사용자가 문제를 풀면 결과가 저장되어, 새로고침해도 남아있다

## 실제 구조 (스켈레톤을 따로 안 만들어서, 지금 배포된 코드 기준)
- `src/app/page.tsx` — 클라이언트 컴포넌트. 문제 큐를 들고 하나씩 보여주고, 제출 시 정답 체크·해설 표시까지 이미 함
- `src/data/questions.ts` — 문제 20개 정적 배열 (`id, topic, questionText, choices, answerIndex, explanation, difficulty`)
- `src/app/api/questions/route.ts` — 위 배열을 그대로 JSON으로 내려줌
- DB·서버 저장 없음 (PLAN.md에 따라 localStorage만 사용)

PLAN.md와 달라진 부분 없음.

## 완료 조건
- [ ] 문제를 제출(정답 선택 후 "제출")하면 결과(문제 id, 정답 여부, 시각)가 localStorage에 저장된다
- [ ] 새로고침해도 지금까지 푼 기록이 사라지지 않는다 (localStorage에서 다시 불러옴)
- [ ] 브라우저를 껐다 켜도 기록이 남아있다

## 안 되는 경우
- localStorage를 못 쓰는 환경(예: 프라이빗 모드 일부)이면 → 저장 없이 그냥 현재 세션에서만 동작 (에러로 화면이 죽지 않게)

## 이번에 안 하는 것
- 총 문제 수·정답률 화면 표시 (기능 2에서)
- 오늘 푼 문제 모아보기 화면 (기능 3에서)
- 여러 기기 간 동기화

## 건드릴 파일
- 새로 만들: `src/lib/storage.ts` (localStorage 읽기/쓰기 함수)
- 고칠: `src/app/page.tsx` (제출 시 저장 호출 + 마운트 시 기존 기록 불러오기)

## 확인 방법
- 문제 하나 풀고 제출 → 브라우저 개발자도구 Application → Local Storage에 기록 생김
- 새로고침 → 기록 유지되는지 (콘솔에서 직접 확인)
- `npm run build` / `npm run typecheck` 통과

## 물어볼 것 (해결됨)
1. **같은 문제를 다시 풀면?** → 매번 새 기록을 추가(append-only 로그). 20문제를 풀다가 막히는 개념이 있으면 그 유형으로 브랜치를 타고, 그 안에서 또 브랜치를 만들 수도 있으며, 다시 원래 흐름으로 돌아온다는 학습 방식이라 같은 문제도 시도할 때마다 계속 쌓는 게 맞음. → 구현: `addAttempt`가 항상 새 레코드를 push (덮어쓰기 없음)
2. **저장 항목에 topic도 같이 넣을까요?** → 넣기로 함. 기능 3(오늘 푼 문제 정리)에서 topic별로 보여줄 수도 있어서 조회 비용을 줄임
3. Vitest 설치 여부 → 이번 기능은 보류. 기능 2(정답률/총 문제 수 계산)에서 필요하면 그때 다시 물어봄

## 남은 열린 질문 (기능 2로 넘어감)
"지금까지 총 N문제 풀었음"을 표시할 때, 브랜치·재시도까지 포함한 **총 시도 횟수**로 보여줄지, 아니면 **20문제 중 몇 개를 커버했는지**(고유 문제 수)를 같이/따로 보여줄지는 기능 2 스펙에서 다시 확인 필요
